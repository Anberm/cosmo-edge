# 算法编排：修改与创建 Pipeline

| 项目 | 说明 |
| --- | --- |
| 适合谁 | 需要修改业务逻辑或组合模型、规则与事件输出的高级用户和开发者 |
| 完成后能做什么 | 看懂节点数据流，修改已有 Pipeline，并创建一个可验收的区域入侵 Pipeline |
| 使用前提 | 已完成场景任务配置；了解通道、检测区域、参数和事件中心 |
| 预计时间 | 修改路径约 20 分钟；新建路径约 35–50 分钟 |
| 是否需要设备 | 需要运行中的 CosmoEdge 和至少一个可播放通道；示例只使用当前已安装的行人模型 |
| 最终验收结果 | 修改后的过滤规则可对比验证；新建 Pipeline 能检测区域内人员并形成可查询事件 |

本页提供两条独立路径：

- **路径 A：修改已有 Pipeline**，适合局部调整节点配置。
- **路径 B：创建新的 Pipeline**，适合定义一条新的处理链。

修改正在被通道使用的任务会影响运行结果。先保存当前配置证据，最好使用测试通道；需要
回退时，使用修改前通过“保存并导出”得到的任务包。

## 1. Pipeline 的四层关系

一个可运行的 Pipeline 需要按数据契约组织四类节点：

| 层 | 当前常见节点 | 输入 | 输出 |
| --- | --- | --- | --- |
| 输入 | 视频解码 | 视频文件或网络流 | 可供推理的图像帧 |
| 模型 | 目标检测算法、目标分类算法、检测视觉大模型、语言视觉大模型 | 图像或上游目标 | 检测框、类别、分数或语义判断 |
| 规则 | 追踪算法、类别过滤、区域告警判断、目标判断、灵敏度计算 | 上游目标及属性 | 被关联、过滤或判定后的目标 |
| 输出 | 事件上报 | 满足规则的结果 | 事件、抓拍图和可选视频片段 |

数据按节点顺序向后传递。下游节点只能使用上游实际产生的内容：

1. 视频解码产生图像帧。
2. 目标检测为图像增加目标框、类别和分数。
3. 追踪为跨帧的同一目标关联标识。
4. 类别、尺寸和区域规则过滤或判定目标。
5. 事件上报把满足条件的结果持久化。

因此不能把“区域告警判断”放在目标检测之前，也不能让需要跟踪标识的事件规则直接读取
未经追踪的单帧结果。添加节点时不仅要问“这个节点做什么”，还要问“它需要什么输入、
会给下游什么输出”。

## 2. 路径 A：修改已有 Pipeline

### 2.1 示例目标与验收设计

本例修改 **未戴安全帽** 中“类别过滤”的 **最小行人尺寸**。

| 项目 | 内容 |
| --- | --- |
| 输入 | 同一段包含近处和远处人员的安全帽视频 |
| 修改前配置 | 当前模板中的最小行人尺寸为 `60`，即短边小于约 60 像素的行人会被过滤 |
| 测试配置 | 将最小行人尺寸临时改为 `100` |
| 预期输出 | 远处小目标减少，近处清晰人员仍进入分类和事件规则 |
| 验收方法 | 在相同视频、区域和时间段对比目标框及事件；验证后决定保留或恢复 `60` |

数值越大，过滤越严格。它不保证自动降低所有误报，也可能增加远处人员漏报，因此必须用
同一输入做前后对比。

### 2.2 打开并备份任务

1. 打开 **场景任务**，找到 **未戴安全帽**。
2. 记录当前使用它的通道。
3. 进入 **算法编排**。
4. 使用 **保存并导出** 备份当前任务，记录文件与时间。

备份不能替代测试隔离。生产通道正在运行时，优先在维护窗口操作或将导入的测试副本绑定
到专用通道。

### 2.3 检查节点位置

当前“未戴安全帽”处理顺序为：

| 顺序 | 节点 | 本例中的作用 |
| ---: | --- | --- |
| 1 | 视频解码 | 产生图像帧 |
| 2 | 目标检测算法 | 检测行人 |
| 3 | 追踪算法 | 关联跨帧人员 |
| 4 | 类别过滤 | 保留行人并过滤尺寸不足的目标 |
| 5 | 目标分类算法 | 判断头盔、无帽等类别 |
| 6 | 目标判断 | 应用分类规则 |
| 7 | 灵敏度计算-计时 | 抑制瞬时结果 |
| 8 | 事件上报 | 生成事件 |

本例直接修改已经存在的 **类别过滤**，不重复添加相同节点。

![类别过滤节点及其标签和尺寸设置](images/img_10.webp)

### 2.4 修改并保存

1. 选择 **类别过滤**。
2. 确认过滤标签为行人，并启用最小尺寸过滤。
3. 打开 **参数设置**。
4. 将 **最小行人尺寸** 从 `60` 改为 `100`。
5. 保存 Pipeline。

![在参数设置中调整最小行人尺寸](images/img_13.webp)

![保存修改后的 Pipeline](images/img_15.webp)

如果保存前页面显示节点未配置、断开的流程或缺少原子模型，不要强行继续；先恢复节点
输入和必填项。

### 2.5 对比验收与回退

1. 将测试通道绑定到修改后的任务并启动。
2. 固定通道、ROI、视频片段和播放起点。
3. 在实时展示中记录近处和远处人员的框。
4. 在事件中心按同一时间范围记录事件。
5. 与修改前证据对比。

通过标准：远处小目标按预期被过滤，近处关键目标仍能被检测、分类并产生合规事件。若
关键目标漏报，逐步降低到 `80` 或恢复 `60`，每次用同一片段复测。

## 3. 路径 B：创建新的 Pipeline

本例创建“区域入侵检测”。当前资源模板已经验证了这组节点关系，教程将它作为最小业务
闭环，而不是从未经验证的组合开始。

### 3.1 定义输入、配置、输出和验收

| 项目 | 内容 |
| --- | --- |
| 输入 | 能正常播放且有人进出指定区域的视频通道 |
| 模型 | 已安装的 `PedestrianDetection` 行人检测原子模型 |
| 规则 | 追踪行人、保留行人类别、判断是否进入主区域 |
| 输出 | 带行人目标的区域入侵事件和抓拍图 |
| 正样本 | 人员清晰进入区域并满足检测持续时间 |
| 负样本 | 人员只在区域外经过 |
| 验收方法 | 正样本有框且有事件；负样本不产生区域入侵事件；重启任务后仍可运行 |

### 3.2 创建任务

1. 打开 **场景任务**，点击 **新建任务**。
2. 任务名称填写“区域入侵检测-验证”。
3. 数据源类型选择 **视频分析**。
4. 任务类型选择 **检测/分析**。
5. 确定后进入 **算法编排**。

![创建视频分析类型的区域入侵任务](images/img_23.webp)

空白流程只有开始和结束。点击两者之间的加号，通过 **添加组件** 插入节点。

![只有开始和结束节点的空白 Pipeline](images/img_27.webp)

![算法动作和业务处理组件面板](images/img_30.webp)

### 3.3 按顺序添加和配置节点

按下面六步完成，不使用概念伪代码：

1. **视频解码**
   放在最前面。它接收通道视频并输出图像帧，通常无业务参数。

2. **目标检测算法**
   选择原子模型 `PedestrianDetection`，选择行人标签。需要降低负载时再基于设备实测
   调整取帧频率。

   ![为目标检测节点选择行人原子模型和标签](images/img_36.webp)

3. **追踪算法**
   输入选择行人检测结果。只有后续需要跨帧目标身份时才启用相应追踪状态；首次验证保留
   当前模板默认值。

4. **类别过滤**
   保留行人标签，最小行人尺寸从当前默认 `60` 开始。过小目标漏报或噪声问题出现后再调。

5. **区域告警判断**
   输入区域类型选择主区域。该节点依据场景任务分配页绘制的区域判断行人是否进入。

   ![区域告警判断节点使用主区域](images/img_42.webp)

6. **事件上报**
   选择带目标跟踪的触发类事件。是否附带视频片段会影响存储和传输，应按项目要求设置；
   本地验收至少保留抓拍图。

   ![配置区域入侵事件的上报方式](images/img_48.webp)

完成后的节点顺序必须是：

1. 视频解码
2. 目标检测算法
3. 追踪算法
4. 类别过滤
5. 区域告警判断
6. 事件上报

保存后重新进入编排页，确认节点和配置仍然存在。

### 3.4 配置任务参数

在 **参数设置** 中先使用可解释的基线：

| 参数 | 基线 | 验证意图 |
| --- | ---: | --- |
| pedestrian 检测方式 | 底部 | 以行人脚部位置判断是否进入地面区域 |
| 最小行人尺寸 | 60 | 过滤过小行人目标 |
| 检测时间 | 0 秒 | 首轮先验证链路；需要抑制瞬时进入时再增加 |
| 告警时间间隔（秒） | 3 | 便于短视频验证；生产环境按处置流程增大 |
| 告警次数 | 1 | 首轮只验证一次触发 |
| 静止目标去重 | 关闭 | 先观察原始行为，再决定是否启用 |

模型置信度由当前原子模型配置提供。不要复制其他模型的阈值；应在页面显示的合法范围内，
用固定样本调节。

### 3.5 分配通道和区域

1. 在 **视频接入** 中选择测试通道并打开 **场景任务分配**。
2. 选择“区域入侵检测-验证”。
3. 在 **检测区域** 中创建主区域，使正样本人员会进入、负样本人员保持在外。
4. 让当前时间落在 **运行策略** 内。
5. 保存并启用服务。

![在通道上启用并保存区域入侵任务](images/img_64.webp)

### 3.6 验收

1. 在实时展示中启用“区域入侵检测-验证”的叠加层。
2. 播放负样本，确认区域外人员不产生入侵事件。
3. 播放正样本，确认人员进入区域后出现目标框和事件提示。
4. 在事件中心检查事件类型、通道、抓拍图和时间。
5. 停止并重新启动任务，重复一段正样本。

![区域内人员触发的实时事件提示](images/img_68.webp)

![事件中心保存的区域入侵记录](images/img_69.webp)

最终通过标准：

- 节点保存后没有丢失或断开；
- 正样本得到行人框并生成一条可解释事件；
- 负样本不生成区域入侵事件；
- 任务重启后仍能处理视频和输出事件。

## 4. 常见问题

### 配置无效

1. 重新进入编排页，确认修改已持久化。
2. 检查测试通道绑定的是否为刚修改的任务，而不是同名旧任务。
3. 检查通道运行开关和运行策略。
4. 确认参数修改发生在实际使用的节点和标签上。
5. 用导出包或修改记录比对当前配置。

### 节点未运行

1. 从视频解码开始逐层确认是否有输出。
2. 检查原子模型已安装并与当前设备后端匹配。
3. 检查节点顺序和上游输入类型。
4. 查看日志中首个初始化或处理失败的节点；后续节点无输出通常是上游失败的结果。
5. 缩减为“视频解码 + 目标检测”，通过后再逐个恢复规则节点。

### 有检测但没有结果输出

1. 确认类别过滤没有删除全部目标。
2. 确认目标实际进入检测区域，且检测方式选择的位置正确。
3. 将检测时间和告警抑制恢复为可验证基线。
4. 检查事件上报节点存在、位于规则之后，并已配置触发类事件。
5. 检查事件中心筛选条件和存储空间。

### 保存失败或节点连接错误

不要连续重复保存。记录页面错误后，检查：

- 是否存在未配置的模型节点；
- 节点之间是否缺少必要的上游数据；
- 是否添加了两个完成相同职责、但互相覆盖的规则节点；
- 导入任务是否引用当前设备不存在的模型。

无法快速定位时，回退到导出的可用版本，再一次只加入一个变化。

## 5. 节点设计检查表

- [ ] 输入节点能够独立产生帧。
- [ ] 每个模型节点在当前设备上有可用原子模型。
- [ ] 每个规则节点所需的目标、类别或跟踪标识都由上游提供。
- [ ] 过滤发生在昂贵的下游处理之前。
- [ ] 事件上报位于最终判定之后。
- [ ] 每个示例都有固定输入、配置、预期输出和正负验收样本。
- [ ] 修改前已有可恢复的导出包或配置记录。
