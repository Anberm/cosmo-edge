# 场景任务配置：通道、区域、参数与告警

| 项目 | 说明 |
| --- | --- |
| 适合谁 | 需要把内置算法配置成实际业务任务的实施人员、集成商和高级用户 |
| 完成后能做什么 | 为一个通道选择算法，设置区域、参数和运行策略，并确认告警规则生效 |
| 使用前提 | 已完成[首次检测](../01-quickstart/quickstart.md)，并有可正常播放的视频通道 |
| 预计时间 | 25–40 分钟 |
| 是否需要设备 | 需要正在运行的 CosmoEdge；可使用仓库内离线视频，不要求摄像机 |
| 最终验收结果 | 实时展示只分析预期区域，参数与策略已保存，事件中心产生可解释的告警记录 |

场景任务配置按以下顺序进行：

1. 选择通道。
2. 选择算法。
3. 绘制检测区域。
4. 设置检测和告警相关参数。
5. 设置运行策略。
6. 验证实时结果与事件记录。

当前页面的实际标签是 **检测区域**、**参数设置** 和 **运行策略**。系统没有单独的
“告警配置”页；告警间隔、次数、持续时间和去重等行为由参数设置与运行策略共同控制。

![通道、算法、区域、参数、展示和事件验证的完整配置路径](images/img_01.webp)

## 1. 三类设置分别控制什么

| 设置 | 控制对象 | 典型影响 | 不负责什么 |
| --- | --- | --- | --- |
| 检测区域 | 画面中的空间范围 | 目标是否进入需要分析的区域 | 不改变模型置信度 |
| 检测参数 | 模型阈值、持续时间、次数、去重等业务条件 | 什么结果被接受、何时形成事件 | 不决定任务在哪些日期和时段运行 |
| 运行策略 | 任务的运行时间安排 | 当前时刻是否执行任务 | 不改变目标识别结果 |

排查时也应按这三个层次区分问题。视频正常但区域没覆盖目标、任务不在运行时段、
或者告警条件尚未满足，都会表现为“没有告警”，但原因不同。

## 2. 完整示例：未戴安全帽

### 2.1 选择通道

准备一个能够正常播放的通道。本例使用仓库中的：

```text
data/test-video/Safety Helmet.mp4
```

若还没有通道，先在 **视频接入** 中以“离线视频”方式上传。保存后先确认视频能播放，
再进入场景任务配置，避免同时排查视频和算法。

### 2.2 选择算法

1. 在视频接入列表中打开该通道的 **场景任务分配**。
2. 在“所有服务”中选择 **未戴安全帽**。
3. 确认它出现在已选服务中。

![从视频通道进入场景任务分配](images/img_03.webp)

![在所有服务中选择未戴安全帽任务](images/img_04.webp)

成功状态：页面显示已选算法，随后可以切换到检测区域、参数设置和运行策略。

### 2.3 绘制检测区域

1. 打开 **检测区域**。
2. 选择 **新增区域**，输入能说明业务位置的名称，例如“北入口作业区”。
3. 拖动多边形顶点，使区域覆盖人员需要佩戴安全帽的位置。
4. 保存区域。

![新增并命名检测区域](images/img_07.webp)

![调整多边形使其覆盖实际作业区](images/img_10.webp)

区域应覆盖完整的人员活动范围，但尽量排除海报、反光屏幕和非作业道路。区域过小会使
目标仅短暂进入，区域过大会引入无关目标。首次调试可适当扩大，确认工作后再收紧。

### 2.4 设置参数

打开 **参数设置**。以下字段来自当前“未戴安全帽”资源模板；不同版本或不同算法会显示
不同字段，应以当前页面为准。

| 当前参数名 | 默认值 | 控制内容 | 调整建议 |
| --- | ---: | --- | --- |
| 安全帽置信度 | 由模板配置 | 安全帽分类结果达到何种分数才被接受 | 误报多时结合现场样本逐步提高；漏报多时谨慎降低 |
| 告警时间间隔（秒） | 60 | 连续事件之间的最短间隔 | 演示可缩短；生产环境避免过密告警 |
| 告警次数 | 1 | 同类事件允许上报的次数；`0` 表示不限制 | 按业务闭环要求设置 |
| 静止目标去重 | 关闭 | 是否对长时间不动的目标抑制重复事件 | 固定画面或海报造成重复事件时开启 |
| 静止目标重叠率 | 0.2 | 判断目标是否为同一静止目标的重叠标准 | 仅在启用静止目标去重后调整 |
| 静止目标去重时间(小时) | 6 | 静止目标多长时间内不重复上报 | 根据现场处置周期调整 |
| 行人检测方式 | 底部 | 以检测框底部、中心或顶部判断目标是否进入区域 | 地面区域通常使用“底部” |
| 最小行人尺寸 | 60 | 小于该尺寸的行人目标不进入后续判断 | 远处漏报时可降低，但会增加噪声与算力消耗 |
| 灵敏度 | 2 | 在连续判断中形成事件所需的命中强度 | 先保留默认值，再用正负样本调整 |
| 检测时间（秒） | 3 | 条件持续满足多久后形成事件 | 希望抑制瞬时误报时增加 |

![未戴安全帽任务的参数设置页面](images/img_11.webp)

不要同时改变多个参数。建议每轮只改一项，记录输入视频、旧值、新值和结果，否则无法
判断哪一项真正影响了误报或漏报。

### 2.5 设置运行策略

打开 **运行策略**，选择任务应运行的日期和时段。首次验证时应让当前日期和当前时间
落在有效时段内。

![为场景任务设置运行日期和时段](images/img_12.webp)

保存任务。保存后返回视频接入列表，确认通道运行开关已开启。

![保存场景任务并启动分析](images/img_14.webp)

### 2.6 验证结果

先看检测，再看告警：

1. 打开 **实时展示**，选择该通道和“未戴安全帽”叠加层。
2. 确认视频持续播放、检测区域位置正确、人员进入区域后出现分类结果。
3. 播放包含未戴安全帽人员的片段，并等待超过“检测时间（秒）”。
4. 打开 **事件中心 → 检测/分析**。
5. 按通道、任务和时间范围筛选，打开抓拍图核对目标、区域与时间。

![实时展示中的未戴安全帽检测结果与事件提示](images/img_21.webp)

![事件中心按通道和时间查询告警记录](images/img_25.webp)

验收记录至少包括：

- 通道名称和算法名称；
- 检测区域截图；
- 本次使用的非默认参数；
- 运行策略；
- 一条正样本事件和一段不应告警的负样本结果。

## 3. 参数示例：离岗检测

“离岗检测”不是通过猜测一个“人数阈值”和“离岗时间”实现。当前模板中的实际字段是：

| 当前参数名 | 默认值 | 含义 |
| --- | ---: | --- |
| 区域中的目标数 | 1 | 区域内用于规则比较的目标数量 |
| 区域中目标数限制类型 | 小于目标数告警 | 当实际人数小于、等于或大于目标数时是否满足规则 |
| 检测时间 | 10 | 人数条件需要持续满足的时长 |
| 检测时间单位 | 秒 | 与“检测时间”组合成实际持续时间 |
| 告警时间间隔（秒） | 60 | 相邻事件的最短间隔 |
| 静止目标去重 | 关闭 | 是否抑制静止目标的重复事件 |

要检测“岗位区域连续 10 秒少于 1 人”，使用默认的 **区域中的目标数 = 1**、
**区域中目标数限制类型 = 小于目标数告警**、**检测时间 = 10** 和
**检测时间单位 = 秒**。然后：

1. 用有人值守片段作为负样本，不应产生离岗事件。
2. 用区域空置超过 10 秒的片段作为正样本，应产生事件。
3. 检查抓拍图的区域和时间是否与预期一致。

这套正负样本验证比单看任务“已保存”更能证明配置生效。

## 4. 如何确认配置已经生效

依次确认四层状态：

1. **持久化**：离开配置页再重新进入，区域、参数和策略仍是保存后的值。
2. **运行**：通道开关已开启，当前时间落在运行策略内。
3. **检测**：实时展示中目标、区域和类别结果符合预期。
4. **事件**：正样本形成事件，负样本不形成事件，抓拍图和时间可解释。

只有“保存成功”不能证明算法已经运行；只有检测框也不能证明告警规则正确。

## 5. 排查顺序

### 配置无法保存或保存后丢失

1. 检查页面是否提示必填字段、区域未完成或参数范围错误。
2. 只保留一个最小区域和默认参数再次保存。
3. 重新进入页面确认是否持久化。
4. 查看浏览器网络请求和后端日志中的保存接口错误。

### 没有检测结果或没有告警

按以下顺序检查，不要先降低全部阈值：

1. 视频是否正常播放。
2. 通道与算法是否关联且运行开关已开启。
3. 当前时间是否位于运行策略内。
4. 目标是否进入检测区域；“行人检测方式”选择的框位置是否合适。
5. 实时展示是否已有检测结果。
6. 正样本是否持续满足“检测时间”和灵敏度条件。
7. 是否受到告警时间间隔、告警次数或静止目标去重抑制。
8. 最后才基于样本调整置信度和最小目标尺寸。

### 误报过多

1. 用事件抓拍图确认误报来自区域外目标、错误类别还是瞬时结果。
2. 先收紧检测区域或改变“行人检测方式”。
3. 对固定干扰目标启用静止目标去重。
4. 再逐步提高相关置信度、灵敏度或检测时间。
5. 每次只改一项，并用同一组正负样本复测。

如果经过区域、规则和阈值调整仍无法满足需求，可能需要换用更匹配的算法或模型，而不是
继续堆叠参数。
