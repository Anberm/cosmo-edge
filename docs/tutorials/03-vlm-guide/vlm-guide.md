# VLM 与 DINO：提示词驱动的视觉任务

| 项目 | 说明 |
| --- | --- |
| 适合谁 | 需要验证长尾视觉需求的方案工程师、算法工程师和高级用户 |
| 完成后能做什么 | 用 VLM 创建状态判断任务，用 DINO 创建开放类别检测任务，并用正负样本评估结果 |
| 使用前提 | 已会配置通道、区域、参数和运行策略；运行环境已安装对应模型与分词器 |
| 预计时间 | 30–45 分钟 |
| 是否需要设备 | 本地 Qwen VLM 需要 Sophon 后端及匹配模型；DINO 需要与当前后端匹配的模型；也可配置兼容的远程 VLM 服务 |
| 最终验收结果 | VLM 对正负样本给出稳定判断，DINO 在目标位置输出检测框，事件记录与提示词定义一致 |

本页从一个任务问题开始：**如何用提示词定义一个可验证的视觉规则？**

![VLM 可描述的状态判断场景示例](images/img_01.webp)

## 1. 先选择正确的能力

| 能力 | 最适合回答 | 输出 | 典型用途 | 主要限制 |
| --- | --- | --- | --- | --- |
| 传统检测/分类模型 | 已知固定类别是否出现 | 检测框、类别、分数 | 人员、安全帽、车辆等高频实时任务 | 新类别通常需要训练和部署模型 |
| VLM | 画面是否符合一段语义描述 | 是/否判断及事件 | 门是否关闭、区域是否整洁、是否存在疑似破坏 | 结果受提示词、画质和场景语义影响；本地 Qwen 当前依赖 Sophon |
| DINO | 某个开放类别在哪里 | 检测框、类别、分数 | 灭火器、垃圾、包裹等开放类别定位 | 目标必须肉眼可辨；小目标、密集目标和模糊概念仍需实测 |

选择原则：

- 要稳定、低延迟地检测固定类别，并且已有合适模型：优先传统模型。
- 要判断“是不是某种状态”，而不是精确定位：先验证 VLM。
- 要找出“某类目标在哪里”：先验证 DINO。
- 涉及精确计数、细粒度身份、极小目标或安全关键闭环：不要只凭一句提示词上线，应使用
  标注样本和量化指标评估，必要时训练专用模型。

模板出现在页面上不代表模型文件已经安装。创建任务前先在 **模型仓库** 确认对应模型可用，
并确认当前设备有足够内存或显存。

## 2. VLM：创建状态判断任务

VLM 将画面或区域图像与提示词一起输入模型，再把判断结果交给事件上报。它通常不提供
目标检测框，因此验收重点是回答和事件，而不是 OSD 框。

### 2.1 先定义可判定的问题

一个可操作的提示词应包含：

1. **观察对象**：河面、消防柜、作业区等。
2. **可见条件**：漂浮物、柜门打开、人员倒地等。
3. **排除项**：水面反光、阴影、正常施工等。
4. **单一结论**：能回答“是”或“否”。

示例：

```text
判断河面区域是否存在塑料袋、瓶子、成片树叶或其他明显漂浮杂物。
忽略水面反光和细小波纹。只回答是或否。
```

| 输入 | 预期结果 |
| --- | --- |
| 河面上有清晰可见的塑料瓶或垃圾袋 | 是，并满足事件规则 |
| 只有水波、倒影或零散不可辨识小点 | 否，不产生该类事件 |

“画面有没有问题”过于模糊；“城墙表面是否有明显的人为刻画、凿击或新鲜缺损，忽略自然
风化和光影”更容易形成一致标准。

### 2.2 用图片分析建立样本基线

新需求先用图片验证，不要直接等待低频视频事件。

1. 打开 **场景任务**，新建数据源类型为 **图片分析** 的任务。
2. 在 **算法编排** 中添加 **语言视觉大模型**。
3. 选择已经安装的原子模型，设置提示词和生成风格，然后保存。
4. 打开 **图片分析**，选择新任务。
5. 分别上传正样本和负样本，开始分析并记录结果。

![创建图片分析类型的 VLM 任务](images/img_16.webp)

![在语言视觉大模型节点中填写提示词](images/img_20.webp)

![上传图片并执行 VLM 分析](images/img_23.webp)

首次验证至少准备：

- 5 张清晰正样本；
- 5 张清晰负样本；
- 真实部署中常见的反光、遮挡、夜间或相似物体样本。

这不是生产精度评估的充分样本量，但能快速发现问题定义、模型可用性和明显误判。保存
每张图片的预期标签与实际结果，提示词调整后对同一批图片复测。

### 2.3 绑定视频并验证事件

图片基线通过后：

1. 创建或打开视频分析任务，在编排中使用 **语言视觉大模型** 和 **事件上报**。
2. 设置取帧频率。频率越高，计算和远程调用压力越大；从低频巡检开始。
3. 将任务分配到视频通道。
4. 用 ROI 只覆盖需要判断的区域。
5. 设置告警间隔和运行策略，保存并启动。

![VLM 节点的模型、取帧频率和提示词设置](images/img_03.webp)

![为 VLM 任务绘制需要判断的区域](images/img_09.webp)

![VLM 判断形成的事件提示](images/img_12.webp)

验收时确认：

- 正样本片段产生预期判断；
- 负样本片段不产生该类事件；
- 事件中心的抓拍图确实来自 ROI 和对应时刻；
- 长时间运行时没有持续模型加载失败、远程超时或资源不足。

::: warning 本地与远程 VLM 的边界
当前本地 Qwen VLM 实现要求 Sophon 后端和匹配的模型资源。使用兼容的远程 VLM 服务时，
还需评估网络稳定性、时延、费用、凭据保管和图像数据合规性。远程接口可调用不等于现场
任务已经通过验收。
:::

## 3. DINO：创建开放类别检测任务

DINO 的提示词是要定位的目标名称，输出是检测框。先用具体、可见的名词，不要把动作、
风险或复杂状态直接当成目标类别。

### 3.1 定义目标

示例输入：

```text
person.garbage
```

当前模板使用英文句号分隔多个目标。预期结果：

- 画面中的人员标为 `person`；
- 可辨识垃圾标为 `garbage`；
- 背景不应产生大量同类框；
- 目标进入配置区域并满足事件条件后，事件中心出现对应记录。

如果多个词效果不稳定，先分别测试 `person` 和 `garbage`，确定是哪一类造成问题。

### 3.2 配置并运行

1. 在 **场景任务** 中打开或创建使用 **检测视觉大模型** 的视频分析任务。
2. 在算法编排中选择 DINO 原子模型，输入目标名称并保存。
3. 在 **视频接入 → 场景任务分配** 中选择该任务。
4. 绘制区域、设置参数和运行策略，然后保存。
5. 打开 **实时展示**，启用该算法的叠加层。

![在检测视觉大模型节点中输入 DINO 目标名称](images/img_26.webp)

![为 DINO 任务绘制检测区域](images/img_29.webp)

![DINO 在实时画面中输出开放类别检测框](images/img_31.webp)

检测框可能晚于原始视频画面更新。验收时应以带时间信息的抓拍和事件记录核对，不要只凭
一次视觉印象判断同步性。

### 3.3 DINO 提示词建议

| 需求 | 首选提示词 | 不建议的写法 |
| --- | --- | --- |
| 人员 | `person` | `someone behaving suspiciously` |
| 灭火器 | `fire extinguisher` | `fire safety is abnormal` |
| 垃圾 | `garbage` 或 `trash`，分别实测 | `the area is dirty` |
| 包裹 | `package` 或 `box`，分别实测 | `dangerous parcel` |
| 车辆 | `car` 或 `vehicle`，按范围选择 | `illegal parking` |

“违停”“危险”“整洁”等包含规则或状态，不能仅靠目标名完成。可以让 DINO 提供候选框，
再在 Pipeline 中叠加区域、持续时间或其他规则。

## 4. 提示词验证记录

每个任务至少记录：

| 项目 | 要记录的内容 |
| --- | --- |
| 任务定义 | 一句话说明什么条件应触发 |
| 提示词版本 | 完整文本和修改时间 |
| 输入样本 | 正样本、负样本和困难样本的固定集合 |
| 运行条件 | 模型、设备后端、ROI、取帧频率和阈值 |
| 实际结果 | 每张图或每段视频的判断、检测框和事件 |
| 接受标准 | 可接受的漏报、误报、时延和资源占用范围 |

只有正样本成功不够；负样本和现场困难样本决定任务能否可靠上线。

## 5. 常见问题

### VLM 没有结果

1. 确认原子模型和分词器已经安装，而不只是存在任务模板。
2. 本地 Qwen 模型确认运行在 Sophon 后端；远程服务确认网络、地址、模型名和凭据有效。
3. 先用单张清晰图片测试，排除视频抽帧与 ROI。
4. 查看日志中是否有模型初始化、内存不足、请求超时或响应解析错误。
5. 图片模式通过后再恢复视频任务。

### VLM 结果不稳定

1. 固定模型、生成风格和同一批样本。
2. 将一个模糊问题拆成一个可见、单一的判断。
3. 在提示词中加入关键视觉特征和明确排除项。
4. 收紧 ROI，避免无关背景。
5. 若相同输入仍无法达到接受标准，改用专用模型或人工复核，不要只继续扩写提示词。

### DINO 没有框或框太多

1. 确认目标在画面中足够大且肉眼可辨。
2. 每次只测试一个具体英文名词。
3. 尝试同义词时分别记录结果，不要一次堆叠多个近义词。
4. 检查 ROI、置信度和模型资源是否正确。
5. 对固定且高频的类别，比较传统检测模型的稳定性和资源成本。

### 目标定义本身含糊

让业务方先标注一组“应该触发”和“不应该触发”的图片。如果不同人员无法对样本达成
一致，提示词或模型也无法形成稳定验收标准。先明确业务边界，再选择技术。
