# 快速开始：部署、登录与首次检测

| 项目 | 说明 |
| --- | --- |
| 适合谁 | 第一次部署或使用 CosmoEdge 的用户、实施人员和开发者 |
| 完成后能做什么 | 登录控制台，接入一个离线视频，为它分配算法并看到检测结果 |
| 使用前提 | x86 主机已安装 Docker，或已有预装 CosmoEdge 的边缘设备 |
| 预计时间 | x86 首次构建约 15–30 分钟；预装设备约 10–15 分钟 |
| 是否需要设备 | 二选一：x86 Docker 主机，或预装 CosmoEdge 的边缘设备；不要求摄像机 |
| 最终验收结果 | 通道处于运行状态，实时展示出现算法叠加结果，事件中心可查询到符合规则的事件 |

本页目标不是“把页面打开”，而是完成一次**可验证的首次检测**。必要路径如下：

1. 部署或连接系统。
2. 登录控制台。
3. 添加测试视频。
4. 为视频选择算法并保存。
5. 在实时展示和事件中心验证结果。

更换默认密码、接入真实摄像机和调整业务参数属于后续操作，不影响本页验收。

## 1. 部署或连接系统

### 路径 A：x86 主机使用 Docker

适用于 Linux x86_64 主机。Windows 用户使用仓库中的
`docker-compose.x86.windows.yml`，其余流程相同。

```bash
git clone https://github.com/cosmo-wander-ai/cosmo-edge.git
cd cosmo-edge
docker compose -f docker-compose.x86.yml up -d --build
docker compose -f docker-compose.x86.yml ps
```

Windows PowerShell：

```powershell
git clone https://github.com/cosmo-wander-ai/cosmo-edge.git
cd cosmo-edge
docker compose -f docker-compose.x86.windows.yml up -d --build
docker compose -f docker-compose.x86.windows.yml ps
```

首次构建会下载依赖并编译，耗时取决于网络和主机性能。

![Docker 正在构建 CosmoEdge 服务镜像](images/build.webp)

成功状态：

- `docker compose ... ps` 中服务为 `Up` 或 `running`；
- 浏览器可以打开 `http://127.0.0.1:8080`；
- 远程访问时，将 `127.0.0.1` 替换为 x86 主机 IP，并确认主机防火墙允许 TCP 8080。

![CosmoEdge 容器处于运行状态](images/container.webp)

### 路径 B：预装 CosmoEdge 的边缘设备

1. 接通设备电源和网线。
2. 将操作电脑接入与设备相同的局域网。
3. 在浏览器中打开设备交付信息中给出的管理地址。

成功状态：登录页可以打开。若不知道设备地址，先查看交付标签或通过路由器
DHCP 租约确认，不要恢复出厂设置。

## 2. 登录控制台

x86 默认地址为 `http://<主机 IP>:8080`。初始账号为：

- 用户名：`admin`
- 密码：`admin`

![CosmoEdge 登录页及用户名和密码输入框](images/x86-login.webp)

点击登录后应进入“运行总览”。首次登录完成后应修改默认密码；密码修改是安全必需项，
但不阻塞本页的首次检测。

## 3. 添加测试视频

仓库内提供可复现的测试素材：

```text
data/test-video/Safety Helmet.mp4
```

1. 打开 **视频接入**。
2. 点击 **添加**。
3. 接入类型选择 **离线视频**。
4. 输入通道名称，例如“安全帽首次检测”。
5. 上传 `Safety Helmet.mp4`，然后保存。

![在视频接入页面添加离线测试视频](images/img_14.webp)

成功状态：列表中出现新通道，并且没有持续显示连接或解码错误。

::: tip 使用摄像机是可选项
完成首次检测后，可把离线视频替换为 RTSP/RTSPS 网络视频源。先用本地素材排除网络、
账号和摄像机编码差异，能更快确认系统本身是否正常。
:::

## 4. 创建首次检测任务

1. 在新增通道的操作区进入 **场景任务分配**。
2. 从“所有服务”中选择 **未戴安全帽**。
3. 在 **检测区域** 中覆盖需要分析的画面；首次验证可以覆盖主要作业区域。
4. 保持内置默认参数。
5. 点击 **保存**。

![为测试视频选择场景任务](images/img_16.webp)

保存会创建通道与算法的关联并启动分析。返回视频接入列表后，确认运行开关已开启。

![场景任务保存后通道进入运行状态](images/img_25.webp)

成功状态：

- 通道已关联“未戴安全帽”；
- 运行开关为开启；
- 页面没有持续出现启动失败提示。

## 5. 验证检测结果

### 5.1 实时展示

打开 **实时展示**，选择刚创建的通道。等待视频播放和模型初始化。

![实时展示中的安全帽检测叠加结果](images/x86-helmet-result.webp)

通过标准：

- 视频持续播放；
- 画面出现目标框、标签或算法状态等叠加信息；
- 刷新页面后仍能重新进入该通道。

### 5.2 事件中心

打开 **事件中心**，按通道和时间范围查询。只有当画面命中检测条件并满足告警时间、
次数和去重规则时才会产生事件，因此“有实时框”与“有事件记录”是两个不同检查点。

![事件中心中的检测事件列表](images/img_32.webp)

## 6. 首次检测验收清单

- [ ] 系统登录页和运行总览可访问。
- [ ] `Safety Helmet.mp4` 已创建为离线视频通道。
- [ ] 通道已分配“未戴安全帽”任务并处于运行状态。
- [ ] 实时展示可以连续播放视频并显示算法结果。
- [ ] 使用包含未戴安全帽目标的片段时，事件中心可以查询到对应事件。
- [ ] 已记录部署方式、访问地址和本次验证时间。

以上项目全部完成，才算完成“首次检测”。

## 7. 常见问题

### 容器没有启动

按顺序检查：

```bash
docker compose -f docker-compose.x86.yml ps
docker compose -f docker-compose.x86.yml logs --tail=200
docker system df
```

确认 Docker 服务正在运行、磁盘空间足够、端口 8080 未被占用。更完整的入口见
[故障排查](../../guide/troubleshooting.md)。

### 登录页打不开或无法登录

1. 确认访问的是主机端口 `8080`，不是容器内部端口。
2. 远程访问时检查主机 IP、防火墙和网段。
3. 首次登录使用 `admin` / `admin`；若密码已修改，使用新密码而不是重建容器。

### 视频保存后没有画面

按“文件可读 → 通道状态 → 解码日志 → 算法状态”的顺序检查：

1. 先使用仓库内的 MP4，避免同时排查 RTSP 网络问题。
2. 确认视频上传完成且通道已启用。
3. 查看服务日志中是否有文件读取、编码格式或解码错误。
4. 若实时视频正常但无算法叠加，重新检查场景任务是否已经保存并运行。

### 有检测框但没有事件

这通常不是连接故障。确认测试片段确实命中规则，再检查告警时间间隔、告警次数、
检测持续时间和静止目标去重。下一篇将逐项解释这些设置。
